## 已实现范围

### 工作台 `/member`

按任务书 §12.1 的区块顺序落地：**成员欢迎区 + 身份摘要 → 维修指标卡 → 技能标签 →
待处理维修 → 快捷操作 → 最近已通过维修 → 后续模块接入位**。

- 数据来自单一聚合接口 `GET /api/v1/member/dashboard`，避免多接口串联造成的级联失败。
- 降级策略按要求实现：**指标区用稳定骨架，失败时仅局部报错**。欢迎区数据在服务端已确定，
  因此任何一次请求失败都不会让整页白屏。
- 四项指标：累计已通过 / 本学期已通过 / 本月已通过 / 累计维修时长。
- 时长底层是整数分钟，展示统一走 `formatDurationMinutes()` 输出「x 小时 y 分钟」。
- 待处理队列三项（草稿 / 待审核 / 已退回）直接复用 M2 的 `/member/repairs?status=…` 筛选入口，
  不新增列表接口、不复制列表逻辑。
- 保留既有 `/member/repairs`、`/member/repairs/new` 入口与导航语义。
- 未开通成员身份的账号渲染明确空态，**不做重定向**（避免与 `/member/repairs/**` 的守卫形成自环）。

### 个人主页 `/member/profile`

- 「查看」与「编辑」分离：只读字段用 `<dl>` 呈现，**不伪装成输入框**；
  实名、学号、班级、QQ、加入时间、角色状态均为只读。
- 可编辑项仅昵称与技能标签，分别对应 `PATCH /member/profile` 与 `PUT /member/profile/skills`。
- QQ 旁标注「内部可见」，如实告知可见性边界。
- 乐观锁：每次保存成功都用响应中的新 `version` 覆盖本地值，避免第二次保存必然 409。
- 冲突与普通失败分别提示：`MEMBER_PROFILE_VERSION_CONFLICT` 引导刷新，其余按普通失败处理。
- 技能选择器使用原生 `<input type="checkbox">`，键盘可聚焦、空格可切换，
  焦点可见由 `:has(input:focus-visible)` 提供；达到上限后未选中项禁用并给出文案。
- `/api/v1/skills` 仍只返回启用技能；编辑器会把个人资料中的已停用历史技能合并回选择器，
  因而成员可以明确取消它们，不会被不可见项目占用 12 项上限。

### 内部成员主页 `/member/profile/[memberProfileId]`

- 只读视图，服务端已按 `ProfileVisibilityPolicy` 裁剪（不含学号、班级与账号状态细节）。
- 打开自己的 ID 时 **307 重定向到 `/member/profile`**，避免两套自我页面语义混淆。
- 不存在、已软删除、非有效成员与无权访问，服务端统一返回 `MEMBER_PROFILE_NOT_FOUND`，
  页面按「不可查看」处理，不区分细因（避免成员枚举）。

### 技能（Skill / UserSkill）

- `skills` 表 + 8 项稳定 code 幂等 Seed（`WINDOWS`、`HARDWARE`、`NETWORK`、`LINUX`、
  `LAPTOP_DISASSEMBLY`、`SYSTEM_INSTALLATION`、`DRIVER`、`STORAGE`）。
- `user_skills` 唯一约束 `(member_profile_id, skill_id)`，**取消选择走软删除**、
  重新选择恢复同一行，不物理删除；并发下不会产生重复关联。
- 主体始终是 `member_profiles.id`，**QQ 绝不出现在任何关联键或列表字段**。
- 数量上限 12（`MEMBER_SKILL_LIMIT`），服务端为权威校验点。
- 已停用技能不能新增关联，但既有保留不被静默删除。

### 维修摘要接入

- M2 的 `listApprovedRepairsForAnalytics()` 与 M3 成员摘要共同复用唯一
  `approvedRepairWhere()` 谓词（口径 `APPROVED AND deletedAt IS NULL`），
  并通过 `source: "M2_APPROVED_REPAIRS"` 在响应中显式标注来源。
- **未复制 M5 统计逻辑**，未在工作台重新实现任何聚合 SQL。
- 学期未配置时 `termApprovedCount` 返回 `{ value: null, status: "UNCONFIGURED" }`，
  页面显示「待配置」，**绝不回退为 0**。
- **日期口径统一**：「本月 / 本学期」是日期相对口径，三个入口
  （工作台、个人主页、他人内部主页）共用 `resolveMemberRanges(now)`，
  同名指标必须相等。缺省调用 `listMemberRepairSummary` 会让 `monthApprovedCount`
  恒为 `0`、`termApprovedCount` 恒为 `UNCONFIGURED`，因此必须显式传入区间。

### API

```text
GET   /api/v1/member/dashboard
GET   /api/v1/member/profile
PATCH /api/v1/member/profile
PUT   /api/v1/member/profile/skills
GET   /api/v1/members/:memberProfileId/profile
GET   /api/v1/skills
```

统一信封 `{ success, data, meta: { requestId } }`，全部响应头固定 `Cache-Control: private, no-store`；
写接口执行 `assertSameOrigin()`。**未引入第二套信封**。

`GET /member/dashboard` 额外返回 `degraded: MemberDashboardDegraded[]`，列出加载失败的区块
（`repairSummary` / `workQueue` / `recentRepairs` / `recentActivity`）。四路查询经
`Promise.allSettled` 逐项收敛，任一路失败**不会**让其余区块一并报错；全部成功时为空数组。
失败区块回退为空数组 / 空队列，`repairSummary` 回退时所有 `MetricValue` 标为 `UNCONFIGURED`，
**绝不**伪造 `0`。

### 环境变量

`.env.example` 新增（均为可选，缺失时学期指标降级为 `UNCONFIGURED`，不影响启动）：

```text
ACADEMIC_TERM_START=
ACADEMIC_TERM_END=
```

校验规则：两者要么同时提供、要么同时缺失；提供时必须是合法日期且起点早于终点，
否则抛 `ACADEMIC_TERM_CONFIG_INVALID`。

另：`DATABASE_URL` 中的 `allowPublicKeyRetrieval` **默认关闭**，仅在显式写
`=true` 时开启（本机开发用 MySQL 8+/9 的 `caching_sha2_password` + 非 TLS 场景需要）。
该开关会让客户端接受服务端下发的 RSA 公钥，存在中间人风险，**生产必须用 TLS**。

### 对 M4/M5/M6 的影响

- M4/M5 占位在响应中固定为 `{ available: false, module: "M4" | "M5" }`，**不携带任何业务数字**，
  前端也不渲染红点或角标。M4/M5 落地时需自行定义各自的接口形状，本模块不预设。
- M6 可直接复用 `PATCH /api/v1/member/profile` 之外的字段（实名/学号/班级）需自建管理接口，
  M3 未开放成员自助修改。
- `MemberProfileSummary` 与 `MemberInternalProfile` 是 M4/M5/M7 的稳定读取契约，
  新增字段属破坏性变更，须走 Contract 变更流程。

## 数据、安全与隐私

### QQ 可见性

| 视图 | 出现场景 | 含 QQ | 含学号/班级 | 含 `userId` |
|---|---|---|---|---|
| summary | 工作台、列表、公开响应 | 否 | 否 | 否 |
| self | 仅 `GET /member/profile` | 是 | 是 | 否 |
| internal | 仅 `GET /members/:id/profile` | 是 | 否 | 否 |

- QQ **不是**用户主键，也不出现在任何关联键、统计口径或列表字段。
- 工作台与技能列表响应经断言确认不含 QQ / `userId`（见集成测试）。

### 软删除

- `MemberProfile`、`Skill`、`UserSkill` 默认读取一律带 `deletedAt: null`。
- 技能取消选择只写 `deleted_at`，不删行；重新选择恢复同一行，历史可追溯。
- `check` 非有效成员（非 `ACTIVE`）时统一按不可查看处理。

### 审计

- 资料更新与技能保存各自在事务内写 `AuditLog`，与业务行**同事务提交或一同回滚**。
- 摘要经 `redactAuditSummary` 脱敏，审计记录不含密码、邀请码与完整联系方式。

### 并发控制

- 昵称更新与技能保存均在 `inSerializableTransaction()` 内「读取版本 → 比对 → 递增 → 写审计」。
- 过期版本返回 `MEMBER_PROFILE_VERSION_CONFLICT` 409，最多重试 3 次（仅对 `P2034` 重试）。
- 集成测试覆盖「并发旧版本保存只有一次成功」。

- **个人主页与工作台日期口径一致**：配置学期后，`getSelf` / `getInternal` / `getDashboard`

  修复前 `before` 恒为 `[]`。同时覆盖幂等重放时 `before === after`。
- **单路失败只降级该区块**：向 `collectSections` 喂入「一路 rejected、三路 fulfilled」，
  断言其余三路仍为 `ready`、失败区块为 `{ status: "failed", code }` 且不携带数据；
  全失败时才 `allFailed: true`，非 `AppError` 异常收敛为 `OVERVIEW_SECTION_FAILED`。
